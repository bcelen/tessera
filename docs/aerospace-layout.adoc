-h, --help:: Print help

--window-id <window-id>::
include::./util/window-id-flag-desc.adoc[]

--workspace <workspace>::
include::./util/workspace-flag-desc.adoc[]

--root::
Instead of the focused window, change the layout of the workspace tiling root node.
When you use this flag, `tiling` and `floating` become invalid values for `<target-layout>`.

--fail-if-noop::
Exit with non-zero exit code if already in the requested layout.
When you use this flag, the command permits only one `<target-layout>` argument.

// =========================================================== Arguments
include::./util/conditional-arguments-header.adoc[]

<target-layout>::
Possible values:
+
* `h_tiles|v_tiles|h_accordion|v_accordion` - Change both tiling layout and orientation in one go
* `tiles|accordion` - Change tiling layout but preserve orientation
* `horizontal|vertical` - Change orientation but preserve layout
* `tiling|floating` - Toggle between floating/tiling mode
* `scrolling` - Lay the workspace out as a strip of columns that scrolls to follow focus. See below
+
If several `<target-layout>` are supplied, then the first one that doesn't describe the currently active layout is applied.

*The scrolling layout.*
Each child of the root container becomes a column with a width of its own, a percentage of the screen set with
`column-width`. Opening a window adds a column next to the focused one instead of squeezing the others. When focus
moves to a column out of view, the strip scrolls just far enough to show it, keeping `scrolling-peek` points of the
neighbouring columns in view at the edges. Columns out of view are hidden the same way windows of other workspaces are.
Stack several windows in one column with `join-with`.

`scrolling` only applies to the workspace root, so a `layout` command that mentions it always acts on the root,
as if `--root` were given. `layout scrolling tiles` toggles the whole workspace between the two.
If another monitor sits next to the edge a column would cross, that column is hidden rather than shown cut.

The strip follows focus, so `focus left|right` and anything else that moves focus scrolls it. With
`scrolling-swipe-modifiers` set, holding those modifiers and swiping two fingers sideways steps one column per
swipe; a mouse wheel, sideways or up and down, steps one column per notch or per bit of smooth spin. `scrolling-animation-duration` makes the strip slide rather than jump.
Dragging a column's edge with the mouse sets its width, and the column keeps it.

// =========================================================== Examples
include::./util/conditional-examples-header.adoc[]

* Toggle between `floating` and `tiling` layouts (order of args doesn't matter): +
`aerospace layout floating tiling`

* Toggle orientation (order of args doesn't matter): +
`aerospace layout horizontal vertical`

* Toggle between `tiles` and `accordion` layouts (order of args doesn't matter): +
`aerospace layout tiles accordion`

* Switch to `tiles` layout. Toggle the layout orientation if already in `tiles` layout: +
`aerospace layout tiles horizontal vertical`

* Toggle the workspace between the scrolling and the tiles layout: +
`aerospace layout scrolling tiles`
